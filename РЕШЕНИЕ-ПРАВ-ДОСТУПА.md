# 🔐 Решение проблемы с правами доступа

## ❌ Проблема:

При попытке остановить процессы появились ошибки:
```
pkill: signalling pid XXX: Operation not permitted
```

Это означает, что некоторые процессы принадлежат другим пользователям или системным процессам.

---

## ✅ Решение 1: Просто запустите сервер

**Часто порты уже освобождены**, даже если некоторые процессы не удалось убить.

### Выполните в терминале:
```bash
npm run dev
```

### Проверьте результат:

**Если увидите:**
```
▲ Next.js 14.x.x
- Local:        http://localhost:3000
✓ Ready
```
✅ **Отлично!** Сервер работает на порту 3000.

**Если увидите:**
```
⚠ Port 3000 is in use, trying 3001 instead.
- Local:        http://localhost:3001
```
⚠️ Порт 3000 все еще занят. Переходите к Решению 2.

---

## ✅ Решение 2: Использовать sudo (требует пароль)

Если порт 3000 все еще занят, попробуйте с правами администратора:

```bash
sudo lsof -ti:3000 | xargs sudo kill -9
sudo lsof -ti:3001 | xargs sudo kill -9
sudo pkill -f "next dev"
```

**Внимание:** Вам потребуется ввести пароль администратора.

---

## ✅ Решение 3: Перезагрузить компьютер

Если ничего не помогает:
1. Сохраните всю работу
2. Перезагрузите компьютер
3. После перезагрузки запустите: `npm run dev`

---

## ✅ Решение 4: Использовать другой порт (временно)

Если нужно срочно протестировать, можно использовать порт 3001:

### 1. Обновите домен в базе данных:

В Supabase SQL Editor выполните:
```sql
UPDATE creators 
SET primary_domain = 'test.localhost:3001' 
WHERE slug = 'test-creator';
```

### 2. Используйте в браузере:
```
http://test.localhost:3001
```

**НО!** Это временное решение. Лучше освободить порт 3000.

---

## 🎯 Рекомендуемый порядок действий:

1. **Попробуйте просто запустить сервер:**
   ```bash
   npm run dev
   ```

2. **Если порт 3000 свободен** - отлично! Используйте:
   ```
   http://test.localhost:3000
   ```

3. **Если порт 3000 занят:**
   - Попробуйте `sudo` команды (Решение 2)
   - Или перезагрузите компьютер (Решение 3)

---

## 💡 Почему это происходит?

Некоторые процессы могут быть:
- Запущены от имени другого пользователя
- Системными процессами
- Заблокированы системой безопасности macOS

Обычно это не критично - просто запустите `npm run dev` и проверьте, на каком порту он запустился.

---

## ✅ Готово!

После выполнения шагов сервер должен работать.
